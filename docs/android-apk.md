# Android APK — what is needed

The Capacitor configuration is complete and committed. Building the APK needs two things
that are not installed on this machine, and neither can be installed without a decision
that belongs to the user (both are multi-gigabyte downloads).

## Current state

| Requirement | Status |
|---|---|
| `capacitor.config.ts` | committed, `webDir: dist`, `CapacitorHttp` explicitly disabled |
| `@capacitor/core`, `@capacitor/android`, `@capacitor/cli` | installed |
| App icons for Android | generated — `bunx tauri icon ./app-icon.svg` writes `src-tauri/icons/android/` |
| Java | **JDK 17 present, but Capacitor 8 requires JDK 21** |
| Android SDK + `ANDROID_HOME` | **absent** |
| Gradle wrapper | generated by `npx cap add android`, which needs the SDK |

## To finish it

```sh
# 1. JDK 21 (JDK 17 will fail the Capacitor 8 Gradle build)
winget install EclipseAdoptium.Temurin.21.JDK

# 2. Android command-line tools, then the platform and build-tools
winget install Google.AndroidStudio        # simplest: bundles the SDK manager
# or, command-line only:
#   download commandlinetools-win-*.zip from developer.android.com
#   set ANDROID_HOME, then: sdkmanager "platform-tools" "platforms;android-35" "build-tools;35.0.0"

# 3. Generate the native project and build
bun run cap:sync      # builds dist with --mode native, then npx cap sync android
npx cap add android
bun run cap:apk       # -> android/app/build/outputs/apk/debug/app-debug.apk
```

`cap:sync` and `cap:apk` both run `build:native`, which bakes `VITE_API_BASE` from
`.env.native`. Without that the APK's webview would resolve `/api/...` against its own
local origin and reach nothing.

## Before the first build

1. **Apply the intent filter.** Re-running `cap add` overwrites `AndroidManifest.xml`, so
   the `ACTION_SEND` block in `WRAPPERS.md` §2 has to be re-applied after generating the
   project. Without it the app never appears in the share sheet.

2. **Add the share-sheet plugin** if share-into-app is wanted:
   `bun add @capgo/capacitor-share-target@^8`, then wire the `shareReceived` listener to
   `parseCardFile()` — the same entry point drag-and-drop uses. Not written yet, because
   it cannot be exercised without a device.

3. **Keep `CapacitorHttp` off.** It is explicitly `false` in `capacitor.config.ts` with the
   reason recorded. Enabling it replaces `window.fetch` with a bridge that awaits the whole
   body, which would silently turn every streamed reply into one lump. `src/lib/native/sse.ts`
   detects the substitution at startup and names the issue.

## Why the APK is not built here

Not a code problem — the configuration is done and the web bundle it would wrap is built
and deployed. It is two missing SDKs and a JDK version bump, which is a ~6 GB download and
an installer the user should choose. See `WRAPPERS.md` §2 for distribution notes
(sideload-only; Play policy bans NSFW companion apps) and `docs/desktop-verification.md`
for the equivalent verification recipe that the desktop build was checked against.
